# ColorOS WIFI感知

作者 **酷安@NVMEX夜莺**

[酷安主页](https://www.coolapk.com/u/1060215)

在 Magisk 或 KernelSU 管理器中从本地选择模块 ZIP，安装时按音量键选择功能，安装后重启。音量＋选择“核心及流体云通知（推荐）”，音量－选择“仅核心”；仅核心模式会移除流体云 DEX，不启动界面子进程。模块卡片的「操作」按钮继续用于切换阈值。

模块需要 Android 10 或更新版本，守护进程在开机后独立运行。使用模块时可关闭欧加网络助手里的弱信号断开开关，避免两边重复触发。

默认阈值为 **−80 dBm**。只有一个 Wi-Fi 连接时才检测。系统事件触发检查，并保留 **7 秒兜底读取**，不主动扫描。默认息屏暂停。打开 WebUI 的「息屏也可断开」后，息屏仍可检测弱信号和已开启的通网检测，并按原条件断开。息屏隐藏流体云。系统进入深度休眠时，检查可能推迟到 CPU 恢复运行。

信号降到阈值时开始倒计时，**默认 7 秒，可调为 1–300 秒**，期间每秒复查。信号回升至「断开阈值 + 回升余量」才取消倒计时，余量可设 **1–10 dB，默认 3 dB**。例如阈值 −80 dBm 时，−77 dBm 才算恢复。启用流体云时可点「立即断开」。切换接入点、修改弱信号设置或网络断开会取消当前判断。

倒计时结束或用户手动操作时，重新核对运行设置、当前网络、BSSID、RSSI 和冷却时间，再请求断开。Wi-Fi 总开关保持开启，可通过 SSID 暂避避免立即连回原网络。每次断开请求后冷却至少 60 秒。多个 Wi-Fi 网络、无 Wi-Fi 或仅移动数据时暂停采样。

## Web 管理面板

在支持模块 WebUI 的 KernelSU/兼容管理器中打开模块页面，可调整 −100 至 −20 dBm 阈值、1–300 秒自动断开倒计时、流体云通知、仅 5GHz、SSID 暂避和通网检测，并查看状态与累计运行指标。保存倒计时立即生效，正在进行的倒计时重新开始，流体云进度条同步使用新时长。仅核心安装没有流体云 DEX，面板会提示重新安装后才能开启通知。原有模块「操作」按钮继续切换阈值。

页面只在打开或手动刷新时请求状态，不启动 HTTP 服务，不后台轮询。普通 Magisk 管理器需使用兼容的 WebUI 宿主；命令行与操作按钮继续可用。

本次自动测试、手机测试边界与功耗分析见 [低功耗优化报告](docs/low-power/REPORT.md)。本地运行 `./test.ps1` 验证策略、生命周期、竞态与 WebUI。操作计数和 CPU ticks 不能直接换算为 mAh。

### 断开后暂避此 SSID（v1.4.0）

默认关闭，默认时长 **300 秒**，可设为 **10–86400 秒**。弱信号倒计时结束、连续通网失败或在流体云点击「立即断开」时，都按同一个设置暂避原 SSID。暂避期间，Android 仍可自动连接其他 SSID，状态栏可能重新出现 Wi-Fi 图标。暂避会影响同名热点漫游，漫游用户可关闭本项。主动手动连接可能覆盖暂避。

模块先保存仅包含网络身份和原始自动连接状态的还原记录，再调用系统接口并回读确认。到期、关闭该功能、正常停止或卸载时尝试恢复；进程异常中断后，下次模块启动会先恢复。系统深度休眠可能延后到期还原，不申请唤醒锁。系统不支持、权限拒绝或还原失败时显示诊断并保留待还原记录。只处理普通已保存网络，跳过 Passpoint、应用建议及临时网络。

Web 面板提供「立即恢复自动连接」。若进程被强制杀死后又停用了模块，模块无法自行运行恢复，可重新启用并重启，或在模块文件仍在时执行：

```sh
su -c 'sh /data/adb/modules/coloros_wifi_sense/webctl.sh restoreautojoin'
```

### Wi-Fi 通网检测（v1.4.0）

独立开关，**默认关闭**。沿用提供的校园网脚本中的目标 `http://connect.rom.miui.com/generate_204`，不执行该脚本的安装或登录逻辑。可自定义返回 HTTP 204 的 HTTP/HTTPS 地址。

每次新连接（或开启检测、修改探测参数后）等待约 3 秒开始，**最多请求两次**。返回 HTTP 204 立即停止，首次失败后按重试间隔再请求一次，连续两次失败才请求断开。重试间隔 **1–3600 秒**，默认 30 秒。检测完成后等待下一次连接。默认息屏取消待执行和在途检测，取消的请求也计入本连接两次上限。开启「息屏也可断开」后，熄屏时继续检测。

探测请求只走当前 Wi-Fi，连接和读取超时各 3 秒。门户认证、探测地址故障、DNS 或防火墙也可能导致检测失败。实际断开前核对运行设置、同一 Network/SSID/BSSID 和冷却时间，开启 SSID 暂避时会暂避原网络。

安装并启用流体云后，断网请求提示「WIFI无法联网，正在断开…」，收到网络丢失确认后显示「WIFI无法联网，已自动断开。」并保留 15 秒；系统拒绝或未确认时提示未能确认断开。仅核心模式不启动通知进程。

本次编译、自动测试和实机验证边界见 [v1.4.0 说明](docs/ssid-probe/REPORT.md)。

### 仅使用 5GHz

默认关闭。在兼容高通驱动上，Web 开关通过运行时 GETBAND/SETBAND 接口立即调整允许频段，开启后仅允许 5GHz，关闭恢复开启前的频段设置。修改可能导致 Wi-Fi 重新连接；没有可用 5GHz 热点时无法连接 Wi-Fi。不支持该接口的设备会显示不可用，不会修改 vendor/odm 配置文件。

模块记录还原信息；重新亮屏或新 Wi-Fi 连接出现时按需重新应用，停用或卸载时尝试还原。息屏不轮询或反复设置频段；显式选择的频段限制在息屏时继续保持。驱动暂不可读时会保留还原记录并提示，恢复后重试。该接口可能作用于整张 Wi-Fi 网卡，其他机型、热点/双 Wi-Fi 并用仍需验证。

本机已验证实时频段 `7 → 1 → 7` 与关闭还原。图片里的 `BandCapability=2` 是另一套配置枚举，不能直接当作运行时命令参数。[v1.3.0 验证范围](docs/5ghz-countdown/REPORT.md)

## 流体云与测试

只需要 root，不需要 LSPosed、额外 APK 或修改 SystemUI。已在一加 PLK110 / ColorOS 17.0.0.105 验证原生卡片、强提醒、开关和进度模板。此通道使用 ColorOS 私有接口，其他版本是否支持需实机验证；界面子进程失败会记录日志，原有 AP 断开策略继续运行。

监控进程保持 root，短时界面子进程在加载 DEX 后切换为系统 UID，通过系统已有的流体云 Provider 投放卡片。开关仅向监控进程回传当前会话事件；监控进程再次核对 AP、阈值和信号后才执行断开。收到网络断开确认后，显示“WIFI信号弱，已手动断开。”或“WIFI信号弱，已自动断开。”，立即收起为顶部胶囊，保留 15 秒后撤回；点击胶囊仍可查看结果。模块停用或监控进程退出时，通过管道关闭界面子进程。

安装后可执行以下命令测试 UI 和开关回调，**测试不会断开 Wi-Fi**：

```sh
su -c 'sh /data/adb/modules/coloros_wifi_sense/demo.sh'
```

首次弱信号使用强提醒主动展开；同一倒计时的后续更新只更新内容和进度。卡片标识固定，避免重复叠加。

## 调阈值

点模块卡片的「操作」，可在 −75、−80、−85、−90 dBm 之间循环。也可在 Root 终端里设为 −100 至 −20 dBm 的任意整数。新值在下一次采样时生效，更新模块时沿用已有阈值。

```sh
su -c 'sh /data/adb/modules/coloros_wifi_sense/settings.sh -83'
```

省略末尾的数字可读取当前阈值。运行日志使用 `ColorOsWifiSense` 标签。

## 打包模块

使用 JDK 17、Android SDK Platform 36、Build Tools 36.0.0 和 Android NDK（本次使用 27.0.12077973）。原生频段组件包含 arm64-v8a、armeabi-v7a、x86_64、x86；以下命令从项目根目录运行，ZIP 输出到 `build/`。

```powershell
./build.ps1 -AndroidSdk 'D:/Android/SDK' -Jdk 'C:/Program Files/Java/jdk-17'
```
