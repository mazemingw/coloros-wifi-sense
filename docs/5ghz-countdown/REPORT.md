# v1.3.0：实时仅 5GHz 与自定义倒计时

日期：2026-11-09。保留模块 ID、原阈值路径、操作按钮、音量键安装选择与默认 7 秒行为；新功能均通过现有 WebUI 管理，不需要额外常驻服务。

## 实现

倒计时配置为 `/data/adb/coloros_wifi_sense/countdown`，不存在时为 7 秒，允许 1–300 秒整数。Web 保存以 0600 临时文件原子替换；FileObserver 更新策略、取消旧会话并重新计时。断开前再次核对文件配置，流体云使用同一个时长和截止时间。

仅 5GHz 默认关闭。`WifiBandControl` 按需调用本模块编译的原生 `wifi-band`，通过高通 nl80211 GETBAND(192)/SETBAND(105) 和嵌套属性 SETBAND_MASK(43) 调整运行时频段。5GHz 位为 1，2.4GHz 为 2，6GHz 为 4；不能把截图中 ini 配置的枚举直接作为此接口参数。[AOSP 接口定义](https://android.googlesource.com/platform/external/wpa_supplicant_8/+/master/src/common/qca-vendor.h)

系统自带 iw 的 GETBAND 在本机可用，但其 vendor send 没有 NLA_F_NESTED 标记，写入被内核拒绝；因此使用约 9 KB/架构的辅助程序正确封装消息，而非修改或重新加载 vendor/odm 文件。[iw 实现](https://kernel.googlesource.com/pub/scm/linux/kernel/git/jberg/iw/+/refs/heads/master/vendor.c)

设置前保存本次启动的原频段，设置后读回确认；有进程间文件锁，写入失败尝试回滚。关闭、停用和卸载时尝试恢复本模块记录的值，不覆盖其他工具已修改的值，不沿用上次启动的旧备份。Wi-Fi 暂不可读时保留还原记录；关闭请求仍可保存，恢复连接后继续处理。

只有用户操作、亮屏和新 Wi-Fi 连接事件按需运行辅助程序。默认未启用时不为此启动子进程；息屏不发起自动频段设置。显式选择的驱动限制会在息屏时继续保持，系统自行在允许的频段内管理连接。驱动重新加载后，下一次亮屏/连接事件才会重新应用，不能承诺恢复前没有短暂的其他频段连接。

## 已完成验证

- JDK 17 / SDK 36 / NDK 27 编译通过，包含四种 ABI；本机实际执行 arm64，其他架构仅编译验证。
- 策略旧测试通过；控制器 32/32、频段事务 14/14、WebUI 13/13。频段事务覆盖备份失败、读回不一致、设置失败、精确还原、外部修改、重启旧备份、无接口待还原和息屏拒绝开启。
- OnePlus PLK110、Android API 37、root：原生 GET/SET 实际完成 `7 → 1 → 7`。Web 同路径的 `webctl.sh band5g` 私有夹测试通过，验证重复开启不覆盖原值、备份权限 0600、模块停用标志和参数校验；最终原值已还原。
- Android 独立测试守护进程：30 秒倒计时改为 2 秒后重新计时，到期进入断开前检查，真正的断开调用由测试代理拦截。非法配置静默、修复恢复通过。
- 息屏测试成功窗口：RSSI 读取 `7 → 7`、周期任务 `2 → 2`；唤醒重新开始，快照余量约 6145 ms。一轮被重新唤醒打断的窗口未计为通过。

测试源码在 `test/` 与 `test/android/`；`band-check.py` 会真实改变驱动频段，使用私有配置夹，并在 finally 中还原。其他 Android 测试的 AP 断开被拦截。此次未覆盖正式已安装模块，未改动正式阈值；测试期间真实频段切换可能造成重连。

## 边界

仅支持同时实现高通 GETBAND/SETBAND 的驱动；未知硬件不修改系统配置，不承诺兼容 MediaTek/Broadcom。驱动可能对同一网卡的热点、双 Wi-Fi 或其他接口产生影响。真实从 2.4GHz 切换到 5GHz AP、热点并用、整机重启、其他 ROM，以及完整 Magisk/KernelSU 管理器安装升级尚未逐一实机验证。无持续扫描、WakeLock 或网络测速；不宣称已经测得电量下降。

按用户要求在已有验证完成后发布，未继续扩展虚拟机或额外长时间测试。
